# AGENTS.md — frutales

Mobile-first app (ALL UI in Spanish, es-CO) to track fruit-processing batches: Fase 1 (compra/procesamiento) and Fase 2 (venta). Two independent npm packages, no root `package.json`: `server/` (Express 5 + Prisma + PostgreSQL, TS) and `client/` (React 19 + Vite + Tailwind v4 + TanStack Query, TS). Deploy guide: `DOCKER.md` (Spanish). Business rules: `README.md`.

## Commands

- server: `npm run dev` (tsx watch, :4000) · `npm run typecheck` · `npm run build` then `npm run start:prod` · `npm run prisma:migrate` (dev: creates + applies + generates) · `npm run prisma:deploy` (prod/CI) · `npm run db:seed` (idempotent initial admin from `ADMIN_*`) · `npm run prisma:studio`
- client: `npm run dev` (:5173, proxies `/api` → :4000) · `npm run typecheck` · `npm run build` (`tsc --noEmit && vite build`) · `npm run test:e2e` (Playwright móvil en `client/e2e/`, proyecto Pixel 7; requiere Postgres y usa `E2E_EMAIL`/`E2E_PASSWORD` o el admin de `server/.env`; `E2E_CHROMIUM` apunta a un Chromium del sistema cuando no hay navegadores descargados, p. ej. Alpine/musl)
- **No unit tests exist.** Verification = typecheck + build + hitting the API against the local Postgres (+ the mobile Playwright E2E above). `server/.env` already targets `postgresql://postgres@localhost:5432/frutales` (2 seed projects + backfilled catalogs live there — don't wipe it).
- Docker (repo root): prod `docker compose up --build -d` — the one-shot `migrate` service runs `prisma migrate deploy && npm run db:seed` before the API starts; no host ports, the client joins external `npm_net` for Nginx Proxy Manager as `frutales-client:80`. Dev: `docker compose -f docker-compose.yml -f docker-compose.dev.yml up --build` (create `npm_net` once first). Root `.env` required (copy `.env.example`) and must define `JWT_SECRET` (min 32 chars) plus optional `ADMIN_*` for the initial admin.
- `backup.sh` dumps the prod DB via `docker compose exec db pg_dump` into `backups/` (7-day rotation). `COMPOSE_DIR` is hardcoded to the production path — edit it if the project moves. `backups/` contains real dumps; never commit them.

## Architecture rules (easy to break)

- Auth: `POST /api/auth/login` sets the `frutales_session` httpOnly JWT cookie; every `/api/*` route except `/api/health` and login is protected by `middleware/require-auth.ts` (it reloads the user from the DB on each request). Users/roles live in the `users` table; `/api/users` is admin-only. Never store plain passwords — always bcrypt via `auth.service.ts`. `JWT_SECRET` is required at boot. The JWT is stateless: logout clears the cookie, but a copied token remains valid until it expires.
- Data (projects/catalogs) is shared by every authenticated user; only user management is restricted to admins. If per-user ownership is ever added, the auth middleware is the place to enforce it.
- Derived values are computed at read time, never stored: `totalCost`/`totalRevenue`/`netProfit`/`paidAmount`/`balance`/`paymentStatus` in `server/src/modules/projects/projects.mapper.ts`. The `paymentStatus` column is only a query cache (refreshed by the projects/payments services) — don't "fix" staleness by persisting derived values.
- Client math mirrors server math: `client/src/lib/calc.ts` ↔ `server/src/modules/projects/projects.calc.ts`. Change both together.
- Net yield: unless `netYieldOverridden: true`, the server ignores the client's `netYield` and recomputes `initialQty × (1 − reductionPct/100)`.
- Gastos (expenses): nested CRUD at `/api/projects/:projectId/expenses` (`expenses.routes.ts`, `mergeParams`). They are NOT part of the project PUT payload — editing a project must never touch its expenses; the UI edits them through `ExpensesSection` (details screen + edit form's "Fase 1" tab; its modals portal to `<body>` so the section is safe inside the form). `totalCost = purchaseCost + expensesTotal`; the details summary shows `Costo por kg de producto = totalCost / netYield` (display-only); the dashboard profit subtracts expenses of *sold* projects only; project deletion cascades to expenses.
- Abonos/pagos (payments): nested CRUD like expenses at `/api/projects/:projectId/payments` (requires a registered sale → 400 otherwise). `paidAmount`/`balance`/`paymentStatus` are derived from the payments in the mapper: fully covered → `Pagado`; a `Contado` sale with NO registered payments also counts as `Pagado` (legacy/automatic — once you register an abono, payments rule); `Vencido` (past due with balance) takes precedence over `Abonado` (partial). The dashboard credit counts use a CTE over `payments` (`paidAmount < revenue`). UI: `PaymentsSection` (details Fase 2 + edit form's Fase 2 tab; modals portal to `<body>`).
- Fase 2 (venta) API contract: send ALL sale fields or NONE (sending none clears the sale; sending any one triggers full-set Zod cross-checks). Never send JSON `null` for optional fields — `z.coerce.number().optional()` coerces `null` → 0. Omit the key instead.
- Money in USD: purchases (`purchaseCurrency`/`purchaseExchangeRate`), sales (`currency`/`exchangeRate`) and every expense carry their own currency plus the COP/USD rate captured at registration (client value, or live TRM via `resolveUsdCopRate` — `GET /api/exchange-rate`, datos.gov.co → open.er-api.com, override with `EXCHANGE_RATE_API_URL`). All totals normalize to COP in the mapper; the dashboard SQL multiplies each side by `COALESCE(<rate>, 1)`. Legacy rows have no currency → treated as COP.
- Comprobantes (receipt images): base64 data URLs stored in the DB (`purchaseImage`, `saleImage`, expense/payment `image`). Only DETAIL responses include them (`toProjectDto(project, { includeImages: true })`); list/dashboard responses strip them — keep it that way (heavy payloads). Photos open in-app through `ImageViewer` (portals to `<body>`; mobile browsers block opening `data:` URLs in a new tab). The client compresses photos to ≤1000px JPEG (`client/src/lib/image.ts`); zod caps each image at 2M chars and `express.json` is set to `4mb`.
- Date-only inputs (`YYYY-MM-DD`) are converted with `parseDateOnly` to **noon UTC** so the es-CO calendar day never shifts — never use midnight.
- `GET /api/dashboard/metrics` intentionally uses `$queryRaw` (aggregating derived formulas across rows — totals, cartera, 6-month series, rankings); don't "simplify" it to `prisma.aggregate`. Its DTO carries `monthly` (zero-filled last 6 UTC months), `paymentBreakdown`, `topProducts`, `topDebtors`, `topProjects` (this replaced the old `chartData`) and `recentProjects`. Dashboard charts are hand-rolled SVG in `client/src/components/charts/` — do NOT add a chart library (mobile bundle).
- Catalogs (`Product`/`Process`/`Client`, unique `name`, duplicates → 409 via the P2002 handler) and the optional `productId`/`processId`/`clientId` FKs on Project are preparatory only: the form still writes free-text `productName`/`processType`/`buyerName`, which remain authoritative.

## Conventions

- ALL user-facing text is Spanish (es-CO): Zod messages, API errors, console logs. Money via Intl es-CO COP (`$ 25.000`), USD `US$ 1,50`; dates DD/MM/YYYY. es-CO Intl needs full ICU — minimal Node builds require installing `icu-data-full` for local verification scripts.
- Backend layout: `modules/<resource>/{schema,service,controller,routes}.ts`; controllers are HTTP-only; Express 5 auto-forwards async errors to `middleware/error-handler.ts`. API envelope: `{ data }` on success, `{ error: { message, details? } }` on failure. Some sandboxes lack `curl`/`wget` — smoke-test with `node -e "fetch(...)"`.
- Money/qty stored as Prisma `Decimal` (12,2 money · 12,3 kg · 12,4 exchangeRate); JS arithmetic via the `round()` helpers.

## Workspace warnings

- Never point `DATABASE_URL` at the shared workspace Supabase (read-only). The `nestjs-react-supabase-readonly` skill does NOT apply to this repo: frutales has its own Postgres and legitimately runs Prisma DDL via migrations — but only against its own database.
- Prisma is pinned exactly to 6.19.3. The Docker prod stage depends on `npm ci --omit=dev --legacy-peer-deps` (npm otherwise installs the optional `prisma` peer CLI, +155 MB) plus deletion of `@prisma/client/runtime/*wasm-base64*`. Revisit both only when bumping Prisma.
